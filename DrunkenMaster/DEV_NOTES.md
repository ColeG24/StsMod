# Drunken Master — dev notes (v0.1 vertical slice)

## Build / publish (macOS)

The game targets .NET 9. A user-local SDK is installed at `~/.dotnet` (the system dotnet is 8).

```bash
export DOTNET_ROOT="$HOME/.dotnet"; export PATH="$HOME/.dotnet:$PATH"
cd ~/dev/StsMod/DrunkenMaster
dotnet build      # .cs changes only → copies .dll to the game's mods folder
dotnet publish    # ANY text/image/localization change → also regenerates the .pck via MegaDot
```

Both `dotnet build` and `dotnet publish` stamp the manifest copied to the mods folder with a git-derived version: `v0.1.<commit count>`, or `v0.1.<commit count + 1>-dirty` if there are uncommitted changes (2026-09-17: the game's SemanticVersion ranks `v0.1.38-dirty` BELOW the Workshop's `v0.1.38` and then silently loads the Workshop copy instead of the local build; check `godot.log` line ~18 to see which one won) (csproj target `StampModVersion`, feeding `CopyToModsFolderOnBuild`). The repo's `DrunkenMaster.json` stays at the base `v0.1.0`; only its major.minor is used. Two machines on the same clean commit therefore show the same version in the mods list, and a `-dirty` or differing number means someone is on different code. (2026-09-14: a per-publish bump was tried first and counted up separately on each player's machine.)

- MegaDot 4.5.1-m.12 (matches the game's engine build) lives at `~/dev/StsMod/tools/MegaDot.app`.
  `Directory.Build.props` points at it. Move it if you like, then update `<GodotPath>`.
- Mods folder: `Steam/steamapps/common/Slay the Spire 2/SlayTheSpire2.app/Contents/MacOS/mods/DrunkenMaster/`
- Logs: `~/Library/Application Support/SlayTheSpire2/logs/godot.log`
- Dev console in game: `` ` `` / `~` / `*`, then `help card` to spawn content. Card ids carry the mod prefix (`card DRUNKENMASTER-HURL`); `upgrade <hand-index>`, `energy <n>`, `relic <id>`, `power <id> <amount> <target-index>` also exist.
- Mod console command (2026-09-17, `ConsoleCommands/IntoxConsoleCmd.cs`, found by the game's `ReflectionHelper.GetSubtypesInMods<AbstractConsoleCmd>`): `intox 1` gains, `intox -2` loses, `intox set 8` sets. Uses the card paths (GainAsync, or Lose + FlushBandPowers + NotifyLost) so Tolerance and Walk It Off react.

## Gotchas learned

- **Co-op soft-lock 2026-09-14 (root cause found later that night, see the hook-context entry above).** Blackout auto-played Distill for the REMOTE player at end of turn; the host paused on `Awaiting remote choice 45` (log: `GenericHookGameAction id 9 ... source CARD.DRUNKENMASTER-DISTILL ... waiting for player choice`) and the client never answered. No checksum errors on the host. Base-game cards prompt under auto-play too (Distilled Chaos into Hologram) and Well-Laid Plans prompts at end of turn, so prompts themselves are legitimate; a random-pick-on-auto-play fallback was tried and REVERTED (user: it removes a choice the game would give). Blackout no longer Exhausts the hand and is written defensively (`Blackout()` doc comment). Needs the client's godot.log to go further.
- **Player choices inside hooks need a per-player hook context.** `Hook.BeforeSideTurnEnd`/`AfterSideTurnEnd` build ONE `HookPlayerChoiceContext` per listener for the whole side; for a `CustomSingletonModel` its owner is `combatState.Players.First()` (the host). A hook context carries exactly one synchronized `GenericHookGameAction`; a second player choice raised while another action is running logs `Tried to interrupt action ... but the currently running action is ...` and proceeds UNSYNCHRONIZED (host auto-continues, client stalls). 2026-09-14: two Blackouts in one BeforeSideTurnEnd call, with Distill + Free Pour+ prompts, desynced co-op (host had Free Pour+ resolved, +9 Block, RNG +9; client had both cards stuck in the Play pile). Fix: Blackout moved to `AfterAutoPostPlayPhaseEntered(choiceContext, player)`, the engine's per-player end-of-turn auto-play hook (Stampede precedent), whose context is owned by that player. Rule: anything that auto-plays cards or prompts at turn start/end goes in a per-player hook (`AfterAutoPrePlayPhaseEntered`, `AfterAutoPostPlayPhaseEntered`, `BeforeFlush`), never in a side-wide one. This also explains the 2026-09-14 Distill soft-lock (same context misuse, choice never synchronized).
- **Never enqueue a GameAction from a hook or power.** Hooks run on every machine; `RequestEnqueue` enqueues locally on the host but sends a request on a client, so the host ends up with the action twice and the client with none (Chaser + Block Potion + Beer Muscles desync, 2026-09-14: host Block 24 / Str 5, client Block 12 / Str 4). Do the work inside the action already running: Chaser now re-runs `PotionModel.OnUseWrapper` from a postfix that wraps the wrapper's Task (`Patches/ChaserPatch.cs`).

- Lasting Candy swaps a reward card for a Power *not already offered*, reusing the reward's rarity odds. If the
  candidates are a single rarity the game throws and the rewards screen soft-locks. With no Common Powers this
  means the pool needs at least four Rare Powers (a boss shows three Rares). Don't let it drop below that.

- The card pool must contain at least one non-Basic card, and ideally one Attack, one Skill and one
  Power, or the game throws `couldn't generate a valid rarity` on every card reward (post-combat,
  Lost Coffer, merchant) and the run soft-locks.
- Strike/Defend have their own art since 2026-09-16 (`strike_drunken_master` / `defend_drunken_master`, bandaged fist on a warm gradient, forearm block on a cool one, deliberately flat backgrounds like the base game's basics). The Ironclad `PortraitPath` / `CustomPortraitPath` overrides are gone.
- Harmony postfixes on `Hook.ModifyDamage` must guard against re-entrancy if they call `Hook.ModifyDamage` themselves (Confusion uses a static flag). Its `out modifiers` is patched as `ref`.
- **Multiplayer determinism:** `Hook.ModifyDamage` is also called by the enemy intent preview, for the LOCAL player only (`LocalContext.GetMe`). Anything a ModifyDamage hook writes to game state is therefore machine-specific and desyncs co-op (2026-09-13: Confusion's per-target self-damage stash was written there; Flail Knight HP diverged by 12 and the client got kicked). Modify hooks must stay pure; record state from a `CreatureCmd.Damage` prefix or a real hook instead. Diagnose desyncs from the host's `godot.log`: it prints LOCAL/REMOTE STATE DUMPs after `State divergence message received`; diff them.
- Custom Godot node classes must be `partial` (Godot source generator) and `MainFile` must call
  `ScriptManagerBridge.LookupScriptsInAssembly`, or `_Draw`/`_Process` overrides never fire.
- In-combat UI is added through BaseLib `ExtraCombatUi.RegisterCombatUiElement` (positioning `Left`
  stacks controls above the draw pile). A `CustomResource` subclass is auto-registered by BaseLib.

## Steam Workshop (set up 2026-09-16)

Release workspace lives in `../workshop/` (see its README). `workshop/upload.sh` publishes, copies the `.json`/`.dll`/`.pck` from the mods folder into `workshop/content/DrunkenMaster/`, downloads Mega Crit's `ModUploader` (v0.2.0, osx) into `tools/ModUploader/` on first run, and uploads via the running Steam client. The Workshop item ID lands in `workshop/mod_id.txt`; commit it so later runs update the same item. `workshop/make-preview.sh` rebuilds `image.png` (1024x576 composite of the select-screen backdrop and figure; Steam caps previews at 1 MB).

The mod is built against the beta `sts2.dll` (`AttackCommand.FromCard(card, cardPlay)` etc.), so the manifest's `min_game_version` is `0.111.0` and the Workshop description tells players to opt into the `public-beta` branch. Main was still v0.107.1 on 2026-09-16; revisit when 0.111 ships to main. After subscribing to your own Workshop item, delete the local `mods/DrunkenMaster` copy (or unsubscribe) so the game does not see the mod ID twice.
